# Control planes are exposed through a shared Gateway by SNI; pods reach their API through a node-local proxy and a fixed advertise address

Decided 2026-10-25.
The three modes, the in-cluster `apiserver-proxy`, the tunnel and Health's probes through it are built.

## Decision

**Three ways out, one default.**
`spec.endpoint` is one of:

| mode | what Lodia creates | public endpoint | in-cluster `kubernetes` Service |
|---|---|---|---|
| `gateway` (default) | three passthrough `TLSRoute`s on the platform's Gateway, all to the Service `<cp>-kube-apiserver`: `hostnames.apiServer` → the API server, `hostnames.konnectivity` → konnectivity-server, `hostnames.tunnel` → the tunnel sidecar | `https://<hostnames.apiServer>:443` | endpoints `240.0.0.1:6443`, the advertise address, served on every node by `apiserver-proxy` |
| `loadBalancer` | one Service of type LoadBalancer: 443 → the API server, 8132 → konnectivity | `https://<host>:443`, `endpoint.loadBalancer.host` or the load balancer's own | by the spec, below |
| `nodePort` | one Service of type NodePort with the same ports | `https://<a management node>:<node port of 443>` | endpoints `<node>:<node port of 443>`, the node's InternalIP of the family of the first service range; development only |

**A load balancer's host.**
The platform names the host in `endpoint.loadBalancer.host`, an IP address it reserved or a name it points at the load balancer, and the spec decides how pods reach it:

| the spec | the public endpoint | published | the `kubernetes` Service's endpoint | pods reach the API |
|---|---|---|---|---|
| `host` is an IP address | `host`:443 | on the first pass | `host`:443 | directly |
| `host` is a name | `host`:443 | on the first pass | the advertise address:6443 | through `apiserver-proxy`, which dials `host`:443 |
| no `host` | the first ingress entry's host name, else its IP, :443 | once the load balancer reports it | the advertise address:6443 | through `apiserver-proxy`, which dials it at 443 |

Behind a load balancer Lodia writes an address into a tenant's `kubernetes` endpoints only when the spec names it as an IP address, which admission checked to be of the first service range's family and outside the tenant's ranges; the node dials anything else.
An EndpointSlice holds IP addresses, and kube-proxy processes no other kind ([types.go](https://github.com/kubernetes/kubernetes/blob/v1.37.2/staging/src/k8s.io/api/discovery/v1/types.go#L40-L50)), so a name would have to be resolved into endpoints.
On kind, a Service whose EndpointSlice held a live address and one that drops SYNs failed 17 of 30 new connections, each after the client's full 10 seconds, since kube-proxy's rules pick an endpoint at random for a connection's first packet ([proxier.go](https://github.com/kubernetes/kubernetes/blob/v1.37.2/pkg/proxy/iptables/proxier.go#L1464-L1472)) and a retransmitted SYN keeps that choice ([nf_nat_core.c](https://github.com/torvalds/linux/blob/v6.17/net/netfilter/nf_nat_core.c#L940-L944)); a Go client dialing a name with both addresses got all 30 through.
Whether the load balancer reports an IP or a host name is known only at run time, while the advertise address and its rules are the schema's, so a tenant without `host` goes through `apiserver-proxy` whatever it reports.
The Service takes the API server at 443 alone in every mode: Lodia writes the `kubernetes` endpoints itself, so nothing needs the Service at the API server's own port, 6443, which the API server and the advertise address keep.

**The `kubernetes` Service's endpoints.**
In every mode the API server runs with `--endpoint-reconciler-type=none` and writes no `kubernetes` endpoints.
Workloads publishes the endpoint of the table's last column as `status.endpoint.inCluster`, and Tenant writes the Endpoints and the EndpointSlice from it, as HyperShift does ([config.go](https://github.com/openshift/hypershift/blob/v0.1.86/control-plane-operator/controllers/hostedcontrolplane/v2/kas/config.go#L211), [reconcile.go](https://github.com/openshift/hypershift/blob/v0.1.86/control-plane-operator/hostedclusterconfigoperator/controllers/resources/kas/reconcile.go#L11-L52)).
Every API server replica serves that address, so no rollout changes them, and no controller rewrites them: the mirroring controller leaves Endpoints labelled `skip-mirror` alone, and the EndpointSlice controller skips a Service without a selector ([endpointslicemirroring_controller.go](https://github.com/kubernetes/kubernetes/blob/v1.37.1/pkg/controller/endpointslicemirroring/endpointslicemirroring_controller.go#L314-L318), [endpointslice_controller.go](https://github.com/kubernetes/kubernetes/blob/v1.37.1/pkg/controller/endpointslice/endpointslice_controller.go#L398-L402)).

**Rollouts.**
Every endpoint above reaches the API server through something that follows its pods' readiness, so a stopping replica keeps serving while it leaves them: its endpoint turns not ready once its pod is deleted ([utils.go](https://github.com/kubernetes/kubernetes/blob/v1.37.0/staging/src/k8s.io/endpointslice/utils.go#L40-L43)), it serves for 15 more seconds, then shuts down, which sends each HTTP/2 client a GOAWAY that moves its next requests to a new connection, and drains its watches for up to 10 seconds (`--shutdown-watch-termination-grace-period=10s`), as Gardener runs it ([deployment.go](https://github.com/gardener/gardener/blob/v1.154.0/pkg/component/apiserver/deployment.go#L51-L52)).
The 15 seconds are a `preStop` sleep before SIGTERM, with `--shutdown-delay-duration=0`, since kube-apiserver closes its connection to the external signer on SIGTERM ([plugin.go](https://github.com/kubernetes/kubernetes/blob/v1.37.1/pkg/serviceaccount/externaljwt/plugin/plugin.go#L77-L80), [server.go](https://github.com/kubernetes/kubernetes/blob/v1.37.1/cmd/kube-apiserver/app/server.go#L73)): during a delay after it every TokenRequest failed, and a controller manager that took its Lease then exited ([kubernetes#142980](https://github.com/kubernetes/kubernetes/issues/142980), `todo.md`).
A request that reaches it on a connection still open, as it starts to drain, is answered with `503` and `Retry-After` ([waitgroup.go](https://github.com/kubernetes/kubernetes/blob/v1.37.1/staging/src/k8s.io/apiserver/pkg/server/filters/waitgroup.go#L79-L96)), which client-go follows.
`--shutdown-send-retry-after` stays off, and `apiServer.extraArgs` refuses it: it answers every request on an open connection during the drain with `429` and `Retry-After` ([with_retry_after.go](https://github.com/kubernetes/kubernetes/blob/v1.37.1/staging/src/k8s.io/apiserver/pkg/server/filters/with_retry_after.go#L55-L105)), which costs each such client a retry a second later.

**Gateway prerequisites.**
Gateway API ≥ 1.5, where `TLSRoute` graduated to the Standard channel ([1.5-CHANGELOG.md](https://github.com/kubernetes-sigs/gateway-api/blob/v1.6.3/CHANGELOG/1.5-CHANGELOG.md#L16-L20)), and an implementation that supports `TLSRoute` in passthrough, its core feature ([tlsroute.go](https://github.com/kubernetes-sigs/gateway-api/blob/v1.6.3/pkg/features/tlsroute.go#L25-L51)): no `ListenerSet`, no `TLSRouteModeTerminate` and no `TLSRouteModeMixed`.
The platform owns the Gateway: a `TLS` listener in `Passthrough` mode on 443 for a wildcard hostname, routes allowed from tenant namespaces by label.
Lodia only attaches.
Workloads reports what stops it in `RoutesReady` ([reasons](../api/controlplane.md#conditions-and-their-reasons)); whether the management cluster serves `TLSRoute` the operator detects when it starts.

**In-cluster access.**
Where a tenant's pods do not dial an IP `host`, in `gateway` mode and in `loadBalancer` mode unless `endpoint.loadBalancer.host` is an IP address (`Endpoint.NodeProxy`), they reach their API through `apiserver-proxy` on their node; an IP `host`, and a node in `nodePort` mode, is the `kubernetes` Service's endpoint itself.
In `gateway` mode a connection from a pod to the `kubernetes` ClusterIP carries no SNI, and every tenant's `kubernetes.default.svc` looks the same, so the shared Gateway cannot route it: Lodia wraps it in a TLS session of its own, the tunnel, with the node half Segla's agent already runs in production.
A load balancer of the tenant's own routes by port, so there the proxy needs no tunnel.

1. The API server runs with `--advertise-address` set to `spec.apiServer.advertiseAddress`, or the default below, which Workloads publishes as `status.endpoint.inCluster`, so the `kubernetes` Service's endpoint is that address and 6443.
   EndpointSlices refuse unspecified, loopback and link-local addresses ([validation.go](https://github.com/kubernetes/kubernetes/blob/v1.37.1/pkg/apis/core/validation/validation.go#L8746-L8766)), so the address is one a network could use.
   A node that holds an address on its loopback answers ARP for it on its LAN by default ([ip-sysctl.rst](https://github.com/torvalds/linux/blob/v6.17/Documentation/networking/ip-sysctl.rst#L2063-L2075)), so a private address such as HyperShift's `172.20.0.1` ([constants.go](https://github.com/openshift/hypershift/blob/v0.1.86/support/config/constants.go#L28-L29)) can answer for a neighbour's gateway.
   The IPv4 default is therefore `240.0.0.1`, from `240.0.0.0/4`, reserved and never forwarded ([RFC 6890](https://www.rfc-editor.org/rfc/rfc6890#section-2.2.2)), where Gardener's advertise addresses come from too ([types_constants.go](https://github.com/gardener/gardener/blob/v1.154.0/pkg/apis/core/v1beta1/constants/types_constants.go#L964-L965), [kubeapiserverexposure.go](https://github.com/gardener/gardener/blob/v1.154.0/pkg/gardenlet/operation/botanist/kubeapiserverexposure.go#L229-L236)): `DefaultAdvertiseAddress` in `api/v1alpha1/names.go`.
   IPv6 has no default: a unique local address must come from a /48 whose global ID is random, never a well-known number ([RFC 4193](https://www.rfc-editor.org/rfc/rfc4193#section-3.2)), the schema cannot draw one, and Lodia never writes `spec`, so a `ControlPlane` whose first service range is IPv6 names its address, from a /48 its platform drew once; Lodia drawing one per `ControlPlane`, kept beside its CAs, can come later without breaking a manifest (`todo.md`).
   The schema's rules for the address are in [`api/controlplane.md`](../api/controlplane.md#spec).
   The setup on the node refuses an address that is on-link on any of its interfaces, and says so.
2. The Tenant controller runs `apiserver-proxy` as a `hostNetwork` DaemonSet in `kube-system` (priority `system-node-critical`, tolerating not-ready nodes, so it starts before the CNI), in two containers of one image, `lodia-tunnel`: `addr`, an init container and a restartable sidecar with `NET_ADMIN` and no listener, puts the address on the node's loopback and keeps it there; `proxy`, as UID 65532 with no capabilities and a read-only root filesystem, listens on the address and 6443.
   The pod mounts no ServiceAccount token; with the tunnel it reads `kube-root-ca.crt` as a ConfigMap volume and its client certificate as a Secret, without it neither.
3. In `gateway` mode, for each connection `proxy` opens TLS to `status.endpoint.tunnel` with the SNI `hostnames.tunnel`, verifying the server against the cluster CA, presents the tunnel client certificate, and copies the pod's bytes inside; behind a load balancer it splices them to `status.endpoint.apiServer` as they are.
   The pod's own TLS session with the API server travels untouched; the API server's serving certificate carries the `kubernetes` ClusterIP, the first address of the tenant's service range, as a SAN, as always, and `status.endpoint.inCluster`'s host, the advertise address, for a client that dials it directly.
4. In `gateway` mode the Gateway passes the outer session through by its SNI, a third passthrough `TLSRoute`, to the `tunnel` port of the API server's Service.
   There a native sidecar of every API server pod, `lodia-tunnel serve`, terminates it with `<cp>-tunnel-serving`, issued by PKI from the cluster CA, requires a client certificate of the tenant's tunnel CA, and splices the inner stream to `127.0.0.1:6443`, so `apiServer.extraArgs` refuses `bind-address`.
   It counts only authenticated sessions against its cap, and bounds the handshakes still pending.

kube-proxy, or any CNI that replaces it, sees a normal Service with a normal endpoint; nothing on the node rewrites packets.
Kubelets and kube-proxy themselves use the public endpoint by name, so they never need the proxy.

**The tunnel's client.**
The outer session is mutual TLS.
A tunnel CA per tenant, a CA per purpose ([staged-credential-rotation](staged-credential-rotation.md)), signs a client certificate of 90 days: PKI writes it as `<cp>-tunnel-client`, Tenant delivers it into a `kube-system` Secret for `apiserver-proxy`, which the kubelet fetches through the public endpoint, and Health presents it when it probes the tunnel.
Ninety days, since a stolen one gives only sessions on the sidecar, until the tunnel CA rotates, while an expired one takes every pod's API, and the renewal at day 60 leaves [30 days without PKI](../operations.md#operator-down).
Neither existing CA fits: kubelets accept the cluster CA for client authentication, and the API server accepts the client CA.
Without it, anyone who reaches the Gateway could hold the sidecar's sessions and lock every pod of the tenant out of its API.

**How `proxy` dials.**
A client's TLS handshake has 10 seconds ([cache.go](https://github.com/kubernetes/client-go/blob/v0.37.1/transport/cache.go#L149)), and its clock runs while `proxy` dials, since `proxy` accepts at once: a dial has 6 seconds in all, and a TCP connect to one address at most 2, or what is left of the 6.
`proxy` starts with the address that last answered, while its lookup still lists it, and moves on to the next when an attempt fails.
An address has answered when the outer handshake is done, or, without the tunnel, when its first byte arrives from it.
It has failed when its connect fails, when the outer handshake fails, or, without the tunnel, when it ends the connection before that byte while the pod's side is still open, once the pod has sent it a byte or within 2 seconds of the connect.
A pod that ends its own side first fails nothing, nor does one that sends nothing until the API server closes the connection, as it does when no handshake has finished within 32 seconds ([secure_serving.go](https://github.com/kubernetes/kubernetes/blob/v1.37.1/staging/src/k8s.io/apiserver/pkg/server/secure_serving.go#L175), [server.go](https://github.com/golang/go/blob/go1.26.8/src/net/http/server.go#L1915-L1919)), while an address that resets as it accepts fails though the pod's first bytes are not yet through.
A failure forgets the address if it is still the answer the connection began with, so that a newer answer stands, and later connections take the lookup's addresses in turn from the one after it, wrapping round, since the connection that met it cannot always move on: without the tunnel the pod's bytes are already on their way to it, and a stalled handshake or silent addresses use up the 6 seconds.
So an address that stops accepting costs 2 seconds to each connection that dials it before its first connect has failed, on each node, and nothing to later ones until their start comes round to it again; one that accepts and then fails costs the connections that meet it before that failure, and the next starts past it.
Without the tunnel `proxy` does not see an address that accepts and never answers: the pod's own handshake gives up first, which fails nothing.
A pod whose side ends before any byte has come back has given up, since its TLS client does not half-close before its handshake has an answer (Go's refuses to, [conn.go](https://github.com/golang/go/blob/go1.26.8/src/crypto/tls/conn.go#L1463-L1466)), so `proxy`, and `serve` behind the tunnel, close both sides at once instead of passing the end on: an API server that never answers holds no slot of `proxy` and no session of `serve`.
The outer handshake runs within what is left of the 6 seconds, not within the 2, so a tunnel that is slow and up is not cut and dialed again.
Three silent addresses ahead of the first live one use all 6 seconds: the connections begun before any of them has failed end there, each later one starts past those its predecessors failed, and the first to reach the live address within the 6 seconds makes it the remembered one.
Racing the addresses a quarter of a second apart ([RFC 8305 §5](https://www.rfc-editor.org/rfc/rfc8305#section-5)) would cut the 2 seconds and spare those first connections, and is left out until a measurement asks for it.

**One image.**
`lodia-tunnel` is a Go binary on `crypto/tls`, built by ko like `lodia-signer`, that reloads its certificates from their mounted directories; its modes `serve`, `addr` and `proxy` are the sidecar and the node's two containers.
Workloads and Tenant render it ([Installation](../README.md#installation)).

**One owner per hostname.**
Two `TLSRoute`s that claim one SNI on a shared listener are not a conflict to Gateway API, which gives the older the traffic ([gateway_types.go](https://github.com/kubernetes-sigs/gateway-api/blob/v1.6.3/apis/v1/gateway_types.go#L459-L469)), but Envoy Gateway v1.9.3 renders one filter chain per route ([route.go](https://github.com/envoyproxy/gateway/blob/v1.9.3/internal/gatewayapi/route.go#L2433-L2461)), Envoy refuses a listener with two chains that match alike ([filter_chain_manager_impl.cc](https://github.com/envoyproxy/envoy/blob/v1.39.5/source/common/listener_manager/filter_chain_manager_impl.cc#L188-L194)), and the tunnel's red team saw the shared listener stop taking every tenant's changes, and vanish when Envoy restarted.
So Workloads reports `HostnameConflict`, naming the holder, and applies none of a `ControlPlane`'s three routes while another `ControlPlane`, in any namespace, names one of its hostnames first on the same Gateway, deleting those it controls, and writes no route whose hostname another route on that Gateway holds.
A hostname belongs to the `ControlPlane` that names it first, by `creationTimestamp` and then namespace and name, so neither a squatter's route nor the gap while a route is recreated takes it; two `ControlPlane`s on different Gateways never conflict, so a squatter on one stops no tenant on another.
A route holds a hostname when its own, intersected with the hostname of a listener it selects at the tenant listener's port, is that name: every SNI Envoy Gateway renders for it and, so that no holder is missed, a name another listener at the port names exactly, which Envoy Gateway drops ([helpers.go](https://github.com/envoyproxy/gateway/blob/v1.9.3/internal/gatewayapi/helpers.go#L361-L381)).
Workloads writes a route only when the cache holds none or one that differs from its render, one at a time per parent Gateway, and never deletes and recreates its own.
Just before it writes, it reads the route under the name from the API server, and the routes that may hold the hostname from the cache's index of routes by hostname, or every route from the API server until a route the running operator wrote has shown in its cache, and again after a write whose outcome is unknown or that its cache did not show within 10 seconds.
Each write waits until the cache holds it before the next on the Gateway is checked, and a watch streams a kind's changes after the `resourceVersion` it starts at and resumes after the last one it returned, missing none ([api-concepts.md](https://github.com/kubernetes/website/blob/snapshot-initial-v1.37/content/en/docs/reference/using-api/api-concepts.md#L404-L413)), and client-go's informer, which the cache is, puts each in its store in the order it arrives ([reflector.go](https://github.com/kubernetes/client-go/blob/v0.37.1/tools/cache/reflector.go#L1006-L1075); [`InOrderInformers`](https://github.com/kubernetes/client-go/blob/v0.37.1/features/known_features.go#L127-L130), GA and locked on), and the list of a relist, which follows a watch it cannot resume, at once ([reflector.go](https://github.com/kubernetes/client-go/blob/v0.37.1/tools/cache/reflector.go#L911-L916), [controller.go](https://github.com/kubernetes/client-go/blob/v0.37.1/tools/cache/controller.go#L999-L1002), [L1075-L1081](https://github.com/kubernetes/client-go/blob/v0.37.1/tools/cache/controller.go#L1075-L1081); [`AtomicFIFO`](https://github.com/kubernetes/client-go/blob/v0.37.1/features/known_features.go#L112-L114), Beta, on by default and not locked, without which the listed objects reach the store one by one, [the_real_fifo.go](https://github.com/kubernetes/client-go/blob/v0.37.1/tools/cache/the_real_fifo.go#L604-L619)), so the cache then holds every route written before it, a previous leader's included: two `ControlPlane`s never both hold a hostname, whatever the cache lags, and a write reads only the routes that may hold its hostname, however many the Gateway has.
The operator refuses to start while client-go reports either gate off, as an environment's `KUBE_FEATURE_AtomicFIFO=false` would make it ([envvar.go](https://github.com/kubernetes/client-go/blob/v0.37.1/features/envvar.go#L169)).
A route of another writer counts once the operator's cache holds it: a check misses one written within the cache's lag before it, as a list from the API server missed one written while the list ran.
Only Lodia writes `TLSRoute`s in the namespaces the listener admits; a platform may bind each hostname to its namespace with a `ValidatingAdmissionPolicy` ([operations](../operations.md#hostnames-on-a-shared-gateway)).

**Konnectivity.**
One `konnectivity-server` per API server replica, beside it in the pod as a native sidecar that stops only after the API server, in gRPC mode on a Unix socket, the egress selector sending only `cluster` traffic through it; agents authenticate with a projected ServiceAccount token, which the server checks with TokenReviews as `system:konnectivity-server` bound to `system:auth-delegator` and to lease verbs in `kube-system`; the server's lease controller is on and agents count servers from leases, so agents hold a tunnel to every replica without a static count and dial only for a server they lack.
Both ends ping after 30 seconds without traffic, as often as the server allows ([server.go](https://github.com/kubernetes-sigs/apiserver-network-proxy/blob/v0.37.0/cmd/server/app/server.go#L511-L515)), so no idle timeout on the way cuts a tunnel.
Agents run as a DaemonSet on the pod network with `--agent-identifiers=ipv4=$(HOST_IP)` and the server tries `destHost` before `default`, so traffic for a kubelet goes through the agent on its own node ([konnectivity setup](https://kubernetes.io/docs/tasks/extend-kubernetes/setup-konnectivity/), [server options](https://github.com/kubernetes-sigs/apiserver-network-proxy/blob/v0.37.0/cmd/server/app/options/options.go), [agent options](https://github.com/kubernetes-sigs/apiserver-network-proxy/blob/v0.37.0/cmd/agent/app/options/options.go)).
The konnectivity version follows the Kubernetes minor (proxy 0.NN for Kubernetes 1.NN, [README](https://github.com/kubernetes-sigs/apiserver-network-proxy/blob/v0.37.0/README.md#L37-L40)).
Wherever `apiserver-proxy` runs the agents resolve the public names through the node (`dnsPolicy: Default`) and count the servers' leases through a kubeconfig to the public endpoint, since an agent with `--count-server-leases` dials no server before its lease informer has synced ([server.go](https://github.com/kubernetes-sigs/apiserver-network-proxy/blob/v0.37.0/cmd/agent/app/server.go#L145-L174)), so that counting does not depend on the path through the node's proxy.
The same tunnels carry the API server's requests to the issuers of its JWT authenticators, whose egress is `cluster` ([structured-authentication](structured-authentication.md)): an agent dials the issuer's address as given and resolves its name itself ([client.go](https://github.com/kubernetes-sigs/apiserver-network-proxy/blob/v0.37.0/pkg/agent/client.go#L449)), so where `apiserver-proxy` runs a Service's name in the tenant does not resolve there.

**Nothing inbound on a node.**
The API server reaches kubelets, webhooks and aggregated APIs through the agents' tunnels.
Lodia's defaults bind what it configures to the smallest address that works: kubelet health on `127.0.0.1:10248`, no read-only port, anonymous kubelet access off; kube-proxy metrics and health on loopback (the health port can be opened for cloud load balancers with `addons.kubeProxy.healthzBindAddress`); agent admin on loopback and health on the pod IP.
The kubelet's own listener address is a node flag (`--address`, `--node-ip`), which the node's owner passes through `kubeletExtraArgs` at join; binding the node IP is recommended.

## Why

- **Cost and limits.**
  A load balancer per control plane is the line item that grows with tenants, and providers cap them; Gardener measured exactly this before moving every shoot behind one load balancer per seed with SNI ([GEP-08](https://github.com/gardener/enhancements/blob/main/geps/0008-shoot-apiserver-via-sni/README.md)).
  A Gateway with `TLSRoute` gives the same with standard API objects.
- **The advertise address keeps Kubernetes semantics.**
  Pointing the `kubernetes` endpoint at an address every node owns locally (HyperShift's `172.20.0.1`, Gardener's per-shoot address in `240.0.0.0/8`) needs no packet rewriting, no dependence on how kube-proxy or the CNI program Services, and works before the CNI is up ([HyperShift haproxy](https://github.com/openshift/hypershift/blob/main/hypershift-operator/controllers/nodepool/apiserver-haproxy/haproxy.go), [Gardener apiserver-proxy](https://github.com/gardener/gardener/blob/master/pkg/component/networking/apiserverproxy/apiserver_proxy.go)).
- **Endpoints a rollout cannot empty.**
  The default `lease` reconciler keeps one record per advertise address, and every replica of a Lodia control plane advertises the same one.
  A stopping replica deletes that record as soon as it gets SIGTERM and, finding no record left, empties the endpoints, until a survivor's next pass up to 10 seconds later ([lease.go](https://github.com/kubernetes/kubernetes/blob/v1.37.1/pkg/controlplane/reconcilers/lease.go#L227-L234), [instance.go](https://github.com/kubernetes/kubernetes/blob/v1.37.1/pkg/controlplane/instance.go#L373-L376)).
  Every rollout stops a replica, a single one included: on kind with the lease reconciler, a tenant's `kubernetes` EndpointSlice was empty for 3 seconds and pods inside it were refused; with `none` it never was (`TestPhase1Gate`, [test/e2e](../../test/e2e/README.md)).
- **A rollout loses no request.**
  Rolled on kind under 20 requests a second from outside the tenant and 20 from inside it, half on new connections, half on reused ones, with clients that follow only a `Retry-After`, once, the API server lost none with the delay above; with `--shutdown-send-retry-after` too, each reused connection was told to retry once (`429`), and without the shutdown delay requests were refused and timed out.
- **TLS inside TLS needs nothing but core Gateway API.**
  Gardener's proxy adds a PROXY protocol header or HTTP CONNECT and needs filters on its Istio gateway ([GEP-30](https://github.com/gardener/enhancements/blob/main/geps/0030-apiserver-proxy/README.md)); an outer TLS session with its own SNI is routed by any Gateway that supports `TLSRoute` in passthrough, Segla's node agent carries in-cluster API traffic this way in production today, and konnectivity-server sits behind SNI beside the API server in Kamaji and HyperShift as it does in Lodia.
  The whole chain ran on kind behind Envoy Gateway 1.9.3 and Istio 1.31.3, where ending the outer session in the sidecar cost 0.05 to 0.08 ms more at p99 on reused connections than ending it on the Gateway.
- **No tenant secret reaches the Gateway, and no tenant can starve another.**
  Every certificate stays per tenant, issued from its own CAs and never read by the Gateway controller; the client certificate keeps strangers from the sidecar, and each tenant's three routes are three filter chains of their own.
- **Konnectivity is upstream** and the API server's own mechanism for reaching nodes; one server per replica on a socket keeps that hop local.

## Rejected

- A dedicated IP or load balancer per tenant as the default — fine for a few tenants, the cost driver at hundreds; kept as `loadBalancer`.
- A port per tenant on a shared address — not 443, and every node network needs a firewall rule per tenant.
- The default `lease` endpoint reconciler — every replica advertises the same address, so a stopping replica empties the `kubernetes` endpoints until a survivor's next pass (Why).
- Agents with `--sync-forever` — every agent dials, at a TokenReview each, every second for as long as it runs ([clientset.go](https://github.com/kubernetes-sigs/apiserver-network-proxy/blob/v0.37.0/pkg/agent/clientset.go#L227-L236)).
- Injecting `KUBERNETES_SERVICE_HOST` into pods with a mutating webhook — a webhook in every tenant, and clients that dial the ClusterIP still need the proxy.
- A VPN between the control plane and the nodes — konnectivity is enough and needs no inbound port.
- Ending the tunnel's outer session on the Gateway, with a `ListenerSet` and a `TLSRoute` in `Terminate` mode — sharing port 443 with the passthrough routes needs `TLSRouteModeMixed`, which is experimental, and a Gateway without it marks every listener on the port conflicted and fails every route there, every tenant's ([GEP-2643](https://github.com/kubernetes-sigs/gateway-api/blob/v1.6.3/geps/gep-2643/index.md#L407-L408), [GEP-2643](https://github.com/kubernetes-sigs/gateway-api/blob/v1.6.3/geps/gep-2643/index.md#L540)); Lodia could not tell beforehand, since Envoy Gateway leaves `supportedFeatures` empty ([gatewayclass.go](https://github.com/envoyproxy/gateway/blob/v1.9.3/internal/gatewayapi/status/gatewayclass.go#L33-L36)).
- `172.20.0.1` and `fd00::1`, HyperShift's defaults, as Lodia's — networks use both ranges, and a node answers ARP for the address on its loopback.
- An IPv6 default drawn once per installation and kept in the operator's configuration — neither the configuration nor `status` moves with a `ControlPlane`, and the address may never change; a ULA fixed in Lodia's code would be the well-known number RFC 4193 rules out.
- The proxy built on Envoy, HAProxy or ghostunnel, or in Rust — a Go binary on `crypto/tls` is enough, and the contract (Service, port, certificate, SNI) stays if G6 or the metrics ever show the proxy as a bottleneck.
- `NET_ADMIN` or root in the process that listens — a compromised proxy would own the node's networking, every other pod's traffic included; Gardener and HyperShift hold the address with a process that takes no network input too ([apiserver_proxy.go](https://github.com/gardener/gardener/blob/v1.154.0/pkg/component/networking/apiserverproxy/apiserver_proxy.go#L299-L386), [setup-apiserver-ip.sh](https://github.com/openshift/hypershift/blob/v0.1.86/hypershift-operator/controllers/nodepool/apiserver-haproxy/assets/setup-apiserver-ip.sh#L3-L4)).

## Consequences

- Agents share the passthrough listener on 443: the konnectivity agent sends its `--proxy-server-host` as SNI ([hard way, spike c](https://github.com/lodia-io/lodia/blob/005734e/docs/hard-way.md#c-spike-does-the-konnectivity-agent-send-sni)).
  Go sends no SNI for an IP address ([`hostnameInSNI`](https://github.com/golang/go/blob/go1.26.10/src/crypto/tls/handshake_client.go#L1305-L1315)), so agents dial `konnectivity.<cp>` by name.
- `apiserver-proxy` runs on every node of a `gateway` tenant and of a `loadBalancer` tenant whose `host` is not an IP address; its scope is exactly one address and one listener, and it is in the inventory like every other in-tenant object.
- The tunnel adds a second TLS session to every in-cluster API connection, not to kubelets or users; the phase 2 gate measures the overhead.
- A `ControlPlane` keeps its advertise address for life, and two whose hostnames collide stop the younger one's routes, not the Gateway.
- `spec.endpoint` does not change after creation in `v1alpha1` but for a load balancer's `annotations` and `sourceRanges`; moving between modes, or to another `loadBalancer.host`, changes the address in every kubeconfig and node.
- A `loadBalancer` tenant without `host` follows its load balancer: one made again with another address moves the tenant's identity, which strands its nodes and tokens, so a tenant that must outlive its load balancer names `host`.
- A `kubernetes` Endpoints or EndpointSlice edited or deleted inside the tenant comes back within Tenant's apply period, not within the lease reconciler's 10 seconds.
