# ControlPlane — field reference (v1alpha1, draft)

`lodia.io/v1alpha1`, namespaced.
One object per tenant cluster.
The Go types in `api/v1alpha1` are written by hand and the CRDs are generated from them; this reference changes with them.
Examples: [`examples/`](examples/).

The name is a DNS-1035 label of at most 32 characters (CEL), since the names Lodia and etcd-druid derive from it have to fit Kubernetes' limits.
The tightest is etcd-druid's label on the etcd's Role, `druid.gardener.cloud-etcd-<name>-etcd` ([role.go](https://github.com/gardener/etcd-druid/blob/v0.39.0/internal/component/role/role.go#L154)), and a label value holds at most 63 characters ([syntax](https://kubernetes.io/docs/concepts/overview/working-with-objects/labels/#syntax-and-character-set)); the Service `<name>-kube-apiserver` needs a name that starts with a letter on management clusters before 1.36 ([RelaxedServiceNameValidation](https://github.com/kubernetes/kubernetes/blob/v1.36.0/pkg/features/kube_features.go#L1881-L1884)).

Phase 2 is built in waves ([roadmap](../roadmap.md#phase-2--production)).
A field, condition or reason marked with a wave exists in the schema now and is written from that wave on; until then nothing writes it, or its writer keeps the behaviour the row describes.

## Conditions and their reasons

Every condition type has one writer, and every reason is a constant in `api/v1alpha1/conditions.go`, named by one rule: `Reconciling` is a writer's own first pass, `Unknown`, at the start of its first visit; `WaitingFor<X>` is an input awaited, `False`: `X` is a condition type without `Ready` (`WaitingForDatastore`), a spec or status field (`WaitingForWindow` waits for `spec.maintenance.window`, `WaitingForNodes` for `status.nodes`), or the kind of a named object that is not ready yet (`WaitingForBackup`); `Unsupported` is what this release does not build, the field named in the message; `<Capability>Unsupported` is an environment that cannot serve the spec; `<Kind>NotFound` is a named object that does not exist; `Refused` is the API server a controller writes to refusing one of its objects, `False`, the object named in the message; `ObjectsControlledElsewhere` is an object under the writer's names that another owner keeps, `False`, the object and its owner named in the message.
A condition's `observedGeneration` is the generation it describes: one whose writer waits for another condition at a new generation keeps the older one ([independent-controllers](../decisions/independent-controllers.md)).
A reason with a phase beside it is not written before that phase.

| `BackupReady` | Datastore | the etcd's continuous snapshots are current, as etcd-druid reports them (`BackupSucceeded`); not part of `Ready`, since the cluster serves without them; from wave 1b, backups | `Reconciling`; `SnapshotsPending` (Unknown: no snapshot taken yet); `WaitingForDatastore`; `BackupFailed` (etcd-druid's `BackupReady` is False, its message quoted); `NoBackupStore` (the class has no backup store) |

| `Ready` | Lifecycle | `CertificatesReady`, `DatastoreReady`, `APIServerReady`, `AccessReady`, `AddonsApplied`, `Reachable` and `ControllersLeading` are True, at whatever generation each describes (`Ready`) | `Deleting` while the `ControlPlane` is being deleted; otherwise the status, reason and message of the first of them, in that order, that is not True, or `Unknown`, `LatestGenerationNotObserved` (kstatus's reason for it, [generic.go](https://github.com/kubernetes-sigs/cli-utils/blob/v0.37.2/pkg/kstatus/status/generic.go#L89-L94)) while that one is missing |

`Ready`'s `observedGeneration` is the oldest that the conditions it is built from describe, and the object's while one is missing or the `ControlPlane` is being deleted, so `Ready` True at the object's generation means available with every change taken up.

When more than one of `Progressing`'s reasons applies, Lifecycle writes the first in this order: `Paused`; what the owner has to fix, `Unsupported`, `Failed`, `MaintenanceFailed`, `TimeZoneUnsupported`; a minor step that cannot start, `WaitingForDatastore`, `WaitingForNodes`, `ControllerManagerHeld`; a change not taken up yet, `LatestGenerationNotObserved`; what rolls, `Upgrading`, `Maintaining`, `RollingOut`; a change Lodia started that waits its turn, `WaitingForWindow`, `Ready`'s reason, `FleetLimit`; then `Idle`.
A reason that no other field reports comes before one that `status.kubernetes.upgrade`, `status.components` or `status.datastore.members` counts anyway.

## Backup

`lodia.io/v1alpha1`, namespaced: a sealed copy of a `ControlPlane`'s etcd, from which a new `ControlPlane` can start ([restore-replaces-the-source](../decisions/restore-replaces-the-source.md)).
The name is at most 235 characters (CEL), so that `<name>.encryption-config`, the copy of the source's encryption keys, fits a Secret's name.
The backup reconciler of the Datastore controller, field manager `lodia/backup`, writes the status and holds the finalizer `lodia.io/restore-source`, all from wave 1b, backups; until then nothing acts on a `Backup`.

| field | written by | meaning |
|---|---|---|
| `spec.controlPlaneRef.name` | the platform | the `ControlPlane` to copy, in the same namespace; the spec never changes (CEL) |
| `status.conditions[]` | backup reconciler | `Ready`, below |
| `status.source.{name, uid}` | backup reconciler | the `ControlPlane` copied; a `ControlPlane` restored from the `Backup` replaces it and runs no controller manager while one with this UID exists |
| `status.kubernetesVersion` | backup reconciler | the version the source ran when the `Backup` was sealed: its `status.kubernetes.version`, or its `status.target.version` until wave 2, upgrades, writes the former, the target's minor being then the one every part runs; a `ControlPlane` restored from the `Backup` with another minor is `BackupIncompatible` |
| `status.network.{serviceCIDRs, podCIDRs, clusterDomain}` | backup reconciler | the source's `spec.network`; a restored `ControlPlane` with another one is `BackupIncompatible` |
| `status.snapshots.{provider, endpoint, bucket, prefix}` | backup reconciler | where the copy is: the class's store when the `Backup` was sealed, and its prefix there, `<class prefix>/<namespace UID>/backups/<Backup UID>`, which nothing writes again; a restore copies from it only while the class names the same store |
| `status.seal.revision` | backup reconciler | the revision of `/lodia.io/backups/<Backup UID>` (`BackupSealKey`) in the source's etcd; the copy holds the source's data at least up to it, and a restore requires the key |
| `status.startedAt`, `status.completedAt` | backup reconciler | when the `Backup` started, and when it was complete |

The `Backup`'s condition:

| condition | writer | True, and its reason | False or Unknown reasons |
|---|---|---|---|
| `Ready` of a `Backup` | backup reconciler | the copy is sealed and complete (`Completed`), for good | `Reconciling`; `ControlPlaneNotFound` (no `ControlPlane` of that name); `Unsupported` (a shared datastore); `NoBackupStore` (the source's class has no backup store; final, and an upgrade goes on without its pre-upgrade `Backup`, as `Progressing` says); `WaitingForDatastore` (the source's `DatastoreReady` is not True); `Snapshotting` (the seal key is in the source's etcd, and a snapshot is on its way to its revision); `Copying`; `Failed` (final, the message saying what failed; a new `Backup` tries again) |

## KubeconfigRequest

`lodia.io/v1alpha1`, namespaced: a short-lived kubeconfig for a key of the requester's own, in their own name ([short-lived-kubeconfigs](../decisions/short-lived-kubeconfigs.md)).
The kubeconfig request reconciler of the PKI controller, field manager `lodia/kubeconfigrequest`, writes the status and deletes the request at its deadline, all from wave 1b, KubeconfigRequest; until then the policy admits or refuses requests and nothing answers them.
The chart's admission policy `kubeconfigrequests.lodia.io` and the permission `create` on `controlplanes/adminkubeconfig` decide who may create one, and with `ClusterAdmin` ([the rules](../decisions/short-lived-kubeconfigs.md#decision)).

| field | written by | meaning |
|---|---|---|
| `spec.controlPlaneRef.name` | the requester | the `ControlPlane`, in the same namespace; the spec never changes (CEL) |
| `spec.user` | the requester | their own username, 1 to 512 characters, with no control character, U+FFFE or U+FFFF, which a kubeconfig's YAML cannot hold (CEL); the certificate's user is `lodia:user:<user>` |
| `spec.access` | the requester | `ClusterAdmin` puts the certificate in `lodia:cluster-admins`; without it, it carries no group |
| `spec.request` | the requester | a PEM PKCS#10 request, at most 5120 characters of base64, enough for an RSA-8192 key's; it is exactly one PEM block of that type (CEL), so no private key is stored with it; Lodia uses only its public key, which must be RSA of 2048 to 8192 bits, ECDSA P-256, P-384 or P-521, or Ed25519: the API server refuses a client certificate with a larger RSA key ([handshake_server.go](https://github.com/golang/go/blob/go1.26.10/src/crypto/tls/handshake_server.go#L955-L960), the Go that builds kube-apiserver 1.35 to 1.37) |
| `spec.expirationSeconds` | the requester | 600 to 86400, 3600 by default; the request's deadline is `metadata.creationTimestamp` plus this |
| `status.kubeconfig` | kubeconfig request reconciler | the public endpoint, the cluster CA bundle and the certificate, with no key: the requester adds theirs |
| `status.expirationTimestamp` | kubeconfig request reconciler | the certificate's `NotAfter`: the deadline, or the request CA's `NotAfter` if that comes first |
| `status.conditions[]` | kubeconfig request reconciler | `Ready`, below |

The `KubeconfigRequest`'s condition:

| condition | writer | True, and its reason | False or Unknown reasons |
|---|---|---|---|
| `Ready` of a `KubeconfigRequest` | kubeconfig request reconciler | `status.kubeconfig` holds the certificate (`Issued`), for good | `ControlPlaneNotFound` (no `ControlPlane` of that name); `WaitingForEndpoint` (no `status.endpoint.apiServer` yet); `WaitingForCertificates` (the request CA or `<cp>-ca-bundle` is not written yet); `RequestInvalid` (final: the request does not parse, its signature does not verify, or its key is none of the above); `PolicyNotEnforced` (final: the admission policy was not in place when the request was created, [short-lived-kubeconfigs](../decisions/short-lived-kubeconfigs.md)) |
